# project-evolve

供 Codex 与 Claude Code 使用的个人项目演进 skill。你指定一个或多个仓库和长期目标，它先分析现状，再按你确认的方向做实验、验证和阶段汇报。

## 个人安装

将本仓库的 `skills/project-evolve` 整个目录复制到对应位置。更新时从同一份源文件同步。

| 客户端 | 个人目录 | 对话中调用 |
| --- | --- | --- |
| Codex | `~/.agents/skills/project-evolve/` | `$project-evolve` |
| Claude Code | `~/.claude/skills/project-evolve/` | `/project-evolve` |

**直接在项目里用**：从业务仓库根目录或子目录启动客户端，调用 skill，给出目标和首次最晚汇报时间，例如“分析首次比价体验，今天北京时间 17:00 前汇报”。默认选中当前仓库。目标已涵盖拟做改动且本阶段汇报时间已约定后，它会在干净的原工作区自动创建并切换到 `evolve/<任务名>`；有用户改动时改用独立工作树。说“继续”会按任务记录复用已有分支。记录位于本机共享 Git 目录下的 `project-evolve/<任务名>/EVOLUTION.md`，多个工作树可共用。

**从独立任务目录用**：适合一个目标涉及多个仓库。启动客户端后加入所需仓库，并指定允许修改的范围。例如：

> 分析首次比价的等待体验，提出一个优先方向。客户端和服务端路径见下方，首次调查可读取两个仓库。今天北京时间 17:00 前汇报。

每个任务自己的 `EVOLUTION.md` 记录授权、汇报时间、实验与进度。切换客户端时，先结束原运行，在同一项目或原任务目录调用 skill 并说“继续”。任务目录及业务仓库无需放入本 skill 仓库。

**拓展场景与边界**：除了修复和完善，skill 会在守住你的主方向的前提下，主动提出“在情理之中，又在意料之外”的拓展。它先在任务记录里写下方向锚点（主方向、不可破坏的承诺、明确不做的事），再从多个角度产生候选，例如核心任务换场景、领先用户、类比领域、魅力质量、放宽一条假设。候选按“情理”和“意外”两个维度筛选。每个拓展都要有证据卡，写明文献、数据或案例的来源、日期和等级，证据不够的只进候选池、不实施。拓展原型默认做成关闭的开关或独立入口，不改变默认体验，所以不需要事先确认；是否转为默认、是否找真实用户试用，由你在汇报时决定。方法与文献依据见 [skills/project-evolve/references/expansion.md](skills/project-evolve/references/expansion.md)。

目标内的可逆修复和离线验证由 skill 自主推进。任务依赖当前功能分支独有的已提交代码时可从该提交开分支。产品体验策略变更、重大取舍和未授权的付费实验在执行前沟通。每次正式复盘后仍需约定下一阶段的最晚汇报时间。

第一版只在活跃会话中推进。中断后可以恢复，逾期先补报。每个演进分支默认本地提交，是否上线由你决定。
